# SimpleRCPv2 改进路线

更新时间：2026-09-17

本文件记录基线完成后的改进方向。这里的内容不属于基线验收条件，每项都应当在基线稳定运行后单独设计、实现和测试。

## IM-001 Agent 与成员修改的三方合并

目标是处理 Agent 读取 V0、成员写出 V1、Agent 写出 V2 的冲突。

需要增加：

- Agent 首次读取文件时保存 base 内容与哈希。
- Agent 在独立工作目录写入文件。
- run 完成后比较 base、共享项目当前版本和 Agent 版本。
- 无重叠变化自动合并。
- 重叠变化进入冲突处理界面。
- 合并确认后再写入共享项目并同步到 Yjs。

这项能力完成后，`concurrent_change` 可以从风险提示升级为可以处理的冲突状态。

## IM-002 同一项目的 Agent 并行执行

基线每个项目使用一个 FIFO 队列。并行版本可以让多个 Agent 同时分析和修改，但每个 run 必须使用独立工作目录。

建议结构：

1. run 创建时从共享项目创建独立 Git worktree 或文件快照。
2. 多个 OpenCode session 在各自工作目录并行执行。
3. 只读分析任务可以直接并行完成并返回结果。
4. 修改任务完成后生成变更集合。
5. 合并阶段按照完成时间进入短队列。
6. 合并前检查共享项目 revision，并执行 IM-001 的三方合并。
7. shell 命令始终限制在当前 run 的工作目录。

这种结构可以把等待时间集中在合并阶段，Agent 的分析、编码和测试过程能够并行。Git 仓库适合使用 worktree；没有 Git 的项目需要文件快照或 copy-on-write 工作目录。

OpenCode server 可以同时管理多个独立 session，并为请求选择不同工作目录。session 只能隔离消息历史和运行状态，不能隔离共享目录中的文件。来源与限制见 [Agent 并行执行调研](../research/2026-09-17/parallel-agent.md)。

## IM-003 任务调度与资源限制

同项目并行后需要增加：

- 系统、项目和成员三个层次的并发上限。
- CPU、内存、运行时间和输出大小限制。
- 队列优先级、公平调度和取消传播。
- OpenCode 进程异常后的工作目录清理。
- 管理页面中的运行数量、等待时间和资源使用情况。

## IM-004 Agent 运行隔离

可信网络不代表 Agent 命令始终安全。后续可以把每个 run 放入容器或受限制的系统进程，明确项目目录、网络访问、环境变量和命令权限。

API Key 应当只传给需要访问 Provider 的进程，项目命令不应获得完整服务环境变量。

## IM-005 trace 查询与分析

JSONL 为后续分析提供原始数据。可以增加：

- 按项目、成员、session、工具、文件和状态查询。
- token、费用、耗时和失败原因统计。
- 文件读取到修改之间的时间线。
- `concurrent_change` 出现频率与涉及文件。
- trace 回放和多个 Agent 实现之间的结果比较。

## IM-006 聊天、成员与运行恢复

可以把聊天、成员资料、连接历史和任务草稿保存到数据库。浏览器重连时按服务端 sequence 补发事件，服务重新启动后继续恢复聊天和未完成页面状态。

## IM-007 大文件与生成目录

大文本文件可以增加分块读取与分块编辑。生成目录可以提供项目级忽略设置，允许成员查看 `dist`、`coverage` 等目录，同时控制 watcher 事件数量。

## IM-008 多种 Agent 与 Provider

保留 `AgentRuntime` 接口后，可以增加 DeepSeek Harness、ACP Agent 或其他运行实现。配置页面需要展示 runtime 能力、Provider、Model、版本和 trace 支持范围，run 记录需要保存实际 runtime 和模型信息。
