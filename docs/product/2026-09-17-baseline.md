# SimpleRCPv2 基线需求

状态：协作功能已完成，Agent 功能待开发

更新时间：2026-09-18

## 1. 目标

SimpleRCPv2 为可信团队提供一个可以直接使用的代码协作工作区。服务端保存项目目录并运行协作服务，浏览器提供项目选择、文件编辑、多人同步、聊天和共享终端；完整基线还包含 Agent 任务与 trace。

基线只要求核心流程完整可用：

1. 用户从网页打开已有项目、登记服务端目录、导入 ZIP 或创建空白项目。
2. 用户填写名称，可选填写角色，进入项目工作区。
3. 多位成员可以编辑文本文件、看到对方光标、聊天和使用共享终端。
4. 每位成员可以创建自己的 Agent 任务，也可以继续自己的任务。
5. 服务端通过 OpenCode 和 DeepSeek 执行任务，页面实时显示 trace。
6. Agent 和终端修改文件后，成员可以从文件树和编辑器看到变化。

服务运行在可信网络中。所有进入项目的成员拥有相同能力，可以编辑文件、管理文件、使用终端和调用 Agent。基线不实现公网多租户、复杂权限、安全隔离环境、多个 Agent 选择、Proposal 审阅和自动合并。

## 2. 项目入口

根路径 `/` 显示已登记项目，按照最近打开时间排序。每项显示名称、服务端路径、最近打开时间、`Open` 和删除操作。内置 Demo 不能删除。删除其他项目会关闭该项目的协作资源，并删除服务端副本与登记记录。

服务端使用 `SIMPLERCP_DATA_DIR` 作为运行数据根目录。未设置时使用 SimpleRCPv2 仓库根目录下的 `.simplercp-data/`；生产部署需要把该变量指向持久化磁盘。数据目录结构如下：

```text
.simplercp-data/
  registry.json
  agent/
    settings.json
  projects/<projectId>/
    project.json
    chat.json
    workspace/
    agent-runs/<runId>/
      run.json
      trace.jsonl
```

`agent/` 和 `agent-runs/` 在 Agent 功能开发后创建。DeepSeek API Key 不写入数据目录，只从服务端环境变量 `DEEPSEEK_API_KEY` 读取；本地开发可以把该变量写在仓库根目录 `.env` 中。

`workspace/` 是浏览器、共享终端和 Agent 共同访问的项目代码来源。浏览器中的 Yjs 文档用于协作同步，服务端文件用于持久保存。SimpleRCPv2 仓库的 `.gitignore` 忽略 `.simplercp-data/`；用户项目内部的 `.git` 与 `.gitignore` 继续属于用户项目。

当前代码已经实现项目列表、默认 Demo、空白项目、已有目录导入、ZIP 导入、项目删除、聊天持久化和按项目隔离的协作运行对象。公共 HTTP 与 WebSocket 类型由 `packages/shared` 维护。Agent 设置、任务执行和 trace 页面继续按照后续章节开发。

入口提供四项操作：

- `Open`：进入已登记项目。
- `Add existing project`：把服务端已有目录复制到新的项目 `workspace/` 并登记。
- `New empty project`：创建新的项目 `workspace/` 并登记。
- `Import zip`：上传 ZIP 并创建新项目。

ZIP 只用于创建新项目，不能覆盖已有项目。服务端使用成熟 ZIP 库读取条目，并执行以下检查：

- 默认压缩包最大 200 MiB，最多 50,000 个条目，解压后总大小最大 1 GiB，单个文件最大 128 MiB。
- 拒绝绝对路径、目录跳转、symbolic link、hard link 和设备文件。
- 过滤路径段 `node_modules`、`.git`、`__MACOSX`，过滤文件名 `.DS_Store`。
- 非法条目或超出限制时终止导入，清理未完成目录，不新增项目记录。
- 成功后显示过滤数量和原因。

已有项目导入不会修改原目录。复制完成以后，服务端副本成为协作项目的代码来源。项目注册记录只在全部文件成功写入后创建。

## 3. 进入项目

进入表单包含：

- 显示名称：必填。
- 角色：可选文本，空值显示为 `Collaborator`。

角色只用于成员列表和 Agent 任务上下文，不改变权限。

浏览器首次使用某个显示名称时生成 UUID `userId`，保存在 `localStorage` 的 `simplercp.userId.<normalizedDisplayName>`。刷新页面并使用相同名称时复用该值；每个标签页生成独立 `connectionId`，服务端以 `userId` 作为成员身份。不同浏览器使用相同显示名称时仍然是不同成员。

## 4. 工作区

桌面页面包含文件树、Monaco 编辑器、共享终端和右侧信息栏。右侧信息栏包含 `Chat`、`Team` 和 `Project`。Agent 页面在 Agent 运行功能开发时加入。

状态栏右侧提供 Terminal、Collaboration 面板显示控制，以及日间模式与夜间模式切换按钮。默认使用夜间模式，成员选择保存在浏览器 `localStorage` 的 `simplercp.theme`，刷新页面后继续使用。主题只属于当前浏览器，不向其他成员广播。页面面板、表单、Monaco 和共享终端使用同一主题。

文件树按需读取：打开项目读取根目录，展开目录读取下一层，点击文件读取内容。浏览器不预先读取完整项目。

新建文件、新建目录、重命名和删除都使用应用内窗口。路径字段明确说明从项目根目录开始；当前文件位于子目录时，新建操作默认带入该目录。操作失败时在窗口内显示服务端错误，成功后在页面显示通知。

路径段 `node_modules`、`.git`、`__MACOSX` 和文件 `.DS_Store` 不显示，也不能通过浏览器文件接口读取、写入、创建或删除。终端和 OpenCode 仍可以访问这些路径。

超过 1 MiB 的文本文件在打开前显示性能提示，成员确认后可以进入协作编辑。二进制文件显示类型和大小，不能进入文本编辑器。

多人编辑使用 Yjs 和 Monaco。当前同步行为包括：

- 成员更新经过 300 ms 合并后写入磁盘；关闭 runtime 和后续 Agent 启动前调用 `awaitIdle()`。
- watcher 收到外部变化后重新读取当前磁盘内容，不使用事件内的旧内容或时间戳。
- 稳定的外部内容使用最小 delta 更新 `Y.Text`，保持未变化区域的 CRDT 字符标识。
- 文件系统来源的 Yjs 更新不再次写回磁盘。
- 外部删除会停用对应协作文档并关闭浏览器中的相关标签页。
- 成员延迟写入与外部程序写入仍然可能同时执行，最终内容取决于实际完成顺序。

编辑器显示 `Saving`、`Saved` 和 `Sync failed`。协作连接、Yjs 文档连接与共享终端显示连接状态。协作连接和终端连接会自动重试；多次失败后显示手动重连操作。项目被其他成员删除时，工作区停止重连并提供返回项目列表的入口。

同步细节和已知限制见 [文档同步调研](../research/2026-09-17/document-sync.md) 与 [已知问题](./known-issues.md)。

聊天消息按项目写入 `chat.json`，每条消息包含递增 `sequence`。进入项目和协作 WebSocket 重连时，浏览器通过 HTTP 重新读取完整聊天记录。输入框使用 Enter 发送，Shift + Enter 换行。成员停留在历史消息位置时，新消息提示不会改变当前阅读位置。共享终端允许直接输入、调整尺寸和重新启动，工作目录为当前项目目录。

## 5. Agent 配置

本节为待开发功能。系统提供一份全局 Agent 配置：

- Agent：`OpenCode`。
- mode：`build`。
- Provider：`DeepSeek`。
- Model：服务端提供默认值，设置页面允许修改。
- API Key：服务端从 `DEEPSEEK_API_KEY` 读取，页面只显示是否已配置。
- Enabled：控制全部项目是否可以启动 Agent。

Provider、Model 和 Enabled 写入 `SIMPLERCP_DATA_DIR/agent/settings.json`。设置文件通过同目录中间文件和 rename 更新。服务启动时读取设置，文件缺失时使用默认值。API Key 可以由部署环境直接提供；本地开发由服务端读取仓库根目录 `.env`。

浏览器、日志、trace、聊天和项目文件不能包含 API Key 明文。OpenCode 只监听回环地址，浏览器不能访问 OpenCode 端口。安装检查只检查 command、版本和配置，不调用模型。

## 6. Agent 任务

本节为待开发功能。每位成员可以创建多个任务：

- 新任务创建新的 `sessionId`。
- 继续任务复用原 `sessionId`。
- 每个 run 有独立的 `runId`、状态、trace 和变化文件列表。
- 当前成员查看自己的完整历史，其他成员查看任务状态和文件摘要。

每个项目维护一个 Agent FIFO 队列，同一项目同一时间只允许一个 Agent 直接修改项目目录。不同项目可以同时执行。队列中的其他任务显示位置和发起成员；排队任务可以取消。运行中的任务可以取消，任务最长运行时间默认 10 分钟。服务重新启动时，遗留的 `queued` 和 `running` run 标记为 `failed`，原因记录为 `server_restarted`。

取消、超时或服务重启后的 session 是否可以继续，按照 OpenCode 查询结果处理：可以查询且状态可用时显示“继续”；无法查询时显示“作为新任务继续”，创建新的 session。取消不改变排队任务所属 session。

Agent 直接写项目目录，因此 Agent 依据旧文件内容写回时可能覆盖成员修改。基线只记录读取观察、成员 revision 和风险，并在 run、trace 与文件标签显示 `concurrent_change`。完整处理列在 [已知问题 KI-001](./known-issues.md#ki-001-agent-可能覆盖成员在同一文件中的修改)。

## 7. trace

本节为待开发功能。每个 run 保存 JSONL，页面按顺序展示并支持下载。记录包含：

- 状态、队列位置、消息、工具调用和命令。
- 文件读取、创建和修改路径。
- 权限事件、token、费用、错误和结束原因。
- 最终消息、变化文件和并发警告。

服务端保存经过敏感值过滤的原始事件和标准事件。未知事件仍然保存并显示为未识别事件。trace 的字段定义由 `shared` package 中的 TypeScript 类型维护。

## 8. 主要接口

项目接口：

- `GET /api/projects`
- `POST /api/projects`
- `POST /api/projects/import`
- `POST /api/projects/import-zip`
- `GET /api/projects/:projectId`
- `DELETE /api/projects/:projectId`

工作区接口全部包含 `projectId`，至少提供目录读取、文件读取、文件创建、目录创建、路径重命名、路径删除和聊天历史读取。

计划中的 Agent 接口：

- `GET /api/agent/settings`
- `PUT /api/agent/settings`
- `GET /api/agent/installation`
- `POST /api/projects/:projectId/agent/runs`
- `GET /api/projects/:projectId/agent/runs`
- `GET /api/projects/:projectId/agent/runs/:runId`
- `GET /api/projects/:projectId/agent/runs/:runId/trace`
- `POST /api/projects/:projectId/agent/runs/:runId/cancel`

项目 WebSocket 承载成员、聊天通知、Activity、文件变化和后续 Agent 事件。Yjs 与共享终端分别使用独立 WebSocket。客户端断线后重新加入项目，并通过 HTTP 读取当前聊天记录；Agent 接入后还需要获取最新任务状态。

## 9. 测试与完成条件

服务端保留路径校验、ZIP 导入、文件同步、项目隔离和聊天持久化测试。Agent 接入时增加设置保存、Agent 队列和 trace 存储测试。测试使用仓库内 `.test-workspaces/`，不使用系统临时目录，不使用 Mock Agent 或伪造模型响应。

当前 Playwright 覆盖项目管理、多人协作、编辑权限、主题和 Demo 录制。Agent 接入时增加以下正式场景：

1. 两位成员分别发起任务，验证项目 FIFO 和成员任务归属。
2. 验证 session 复用、trace、文件变化、取消和 JSONL 下载。

协作功能的完成条件是 `pnpm build`、服务端测试和项目协作 E2E 通过。完整基线还要求使用专用 DeepSeek API Key 的正式 Agent E2E 通过。

详细开发顺序见 [基线开发计划](./2026-09-17-development-plan.md)。
