# SimpleRCPv2 已知问题

更新时间：2026-09-17

本文件记录基线明确接受的问题。每项都包含可观察现象、影响范围、当前处理和完整处理方向。开发过程中发现新的可复现问题时，应当在修复代码或接受该问题的同一次提交中更新本文件。

## KI-001 Agent 可能覆盖成员在同一文件中的修改

### 触发过程

1. Agent 读取文件版本 V0。
2. 成员把该文件修改为 V1。
3. Agent 根据 V0 生成 V2，并把 V2 写入项目目录。
4. V2 没有包含成员在 V1 中增加的内容。

### 影响

磁盘最终保存 V2，文件同步层会把 V2 同步到 Yjs。成员的部分修改可能消失。最小 delta 可以保护未变化区域的 CRDT 字符标识，但无法恢复 V2 中已经缺少的内容。

### 基线处理

- Agent run 期间持续记录成员修改过的文件和 revision。
- 从 OpenCode trace 可以得到文件读取事件时，记录读取路径、读取时间和当时的内容哈希。
- Agent 写入同一路径时，如果读取后出现成员修改，run 标记 `concurrent_change`。
- trace、run 详情和文件标签显示警告，保留最终磁盘内容供成员检查。
- trace 无法提供可靠读取事件时，警告以 run 启动时间为检测起点，并标记为保守检测。

这套处理只能提示风险，无法保证找回已经被覆盖的内容。shell 命令间接修改文件时，trace 事件的粒度也可能不足。

### 完整处理方向

- 在 Agent 第一次读取文件时保存 base 内容与哈希。
- Agent 修改写入独立工作目录。
- run 完成后以 base、成员当前版本和 Agent 版本执行三方合并。
- 无重叠修改自动合并；重叠修改进入明确的冲突处理界面。
- 合并完成前不改变共享项目目录。

## KI-002 外部进程与成员同时写入时采用完成顺序

### 触发过程

终端程序或 Agent 直接写文件时，成员也可能通过 Yjs 修改同一文件。两次写入都发生在项目目录，系统无法阻止外部进程在任意时刻覆盖文件。

### 影响

最终内容由实际完成顺序决定。同步层可以防止旧 watcher 回调再次覆盖较新的 Yjs 内容，但无法推断两次写入的业务含义。

### 基线处理

- 同一文件由一个操作队列处理 Yjs 写入和 watcher 重新读取，操作按照到达顺序执行。
- watcher 读取期间 revision 已变化时，把 watcher 操作重新排到队尾。
- 最终内容由队列中最后完成的有效操作决定。
- Agent run 对成员并行编辑显示 `concurrent_change`。

### 完整处理方向

与 KI-001 共用独立工作目录和三方合并流程。共享终端产生的外部写入继续使用完成顺序，因为终端命令没有可用的 base 版本信息。

## KI-003 固定忽略路径的变化不会出现在协作界面

`node_modules`、`.git`、`__MACOSX` 和 `.DS_Store` 不进入文件树、浏览器文件接口和 watcher 事件。终端与 OpenCode 仍然可以访问这些路径。

Agent 或命令修改这些路径时，浏览器不会显示文件变化，也不会创建 Yjs 文档。该行为用于控制依赖安装和 Git 操作产生的事件数量。需要查看结果时使用共享终端。

## KI-004 大文本文件只读

超过 `SIMPLERCP_COLLAB_TEXT_MAX_BYTES` 的文本文件可以查看，但不进入 Yjs 协作编辑。基线默认限制为 2 MiB。

该限制保证外部写入始终通过最小 delta 并入 Yjs，避免大文件整体替换导致光标位置和更新体积异常。未来需要编辑大文件时，应当增加分块文档模型或经过性能验证后提高限制。

## KI-005 服务中断会终止正在运行与排队的 Agent run

服务重新启动时，历史记录中状态为 `running` 或 `queued` 的 run 会改为 `failed`，原因记录为 `server_restarted`。服务不会自动重新执行任务。OpenCode 仍能查询原 runtime session 时允许继续；无法查询时 session 标记为 `unavailable`，用户可以把历史任务作为新任务继续。

## KI-006 同一项目的 Agent 任务需要排队

基线允许每位成员提交自己的任务，但同一项目同一时间只执行一个 Agent run。运行时间较长时，后续成员需要等待。

该限制用于防止多个 Agent 直接修改同一项目目录。不同项目拥有独立队列，可以同时执行。完整并行方向见 [改进路线 IM-002](./improvement-roadmap.md#im-002-同一项目的-agent-并行执行)。

## KI-007 公网访问依赖外部身份认证与隔离

服务端支持配置监听地址和公开访问地址，客户端也可以监听外部网络接口。当前成员进入项目后可以管理文件并运行任意 shell 命令，系统内部没有账号认证与命令隔离环境。

公网使用时需要在反向代理、VPN 或其他可信入口中完成身份认证，并限制可以访问服务的人员。后续可以增加服务端身份验证、项目成员管理和独立运行环境。

## KI-007 共享终端修改文件时没有语义冲突检测

共享终端中的脚本可以直接修改项目文件。watcher 会把最终内容同步到编辑器，但系统无法知道脚本读取了哪个旧版本，也无法执行可靠的三方合并。

基线按照文件写入完成顺序处理，并在终端提交命令前等待当前协作文档写入完成。需要更强保护时，应当让命令在任务工作目录运行，并把文件变化作为变更集合处理。

## KI-008 服务端聊天和在线状态保存范围有限

项目登记、Agent 设置、run 和 trace 会保存。基线的聊天与成员在线状态可以保存在内存中，服务重新启动后允许清空。浏览器断线重连只恢复当前服务进程内仍然保存的消息。

## KI-009 OpenCode 或 Provider 故障会导致 run 失败

OpenCode 进程退出、DeepSeek 请求失败、网络中断或达到超时都会使当前 run 失败。队列继续执行下一项，既有 trace 保留。基线不自动重试修改类任务，避免同一任务重复写入文件。
