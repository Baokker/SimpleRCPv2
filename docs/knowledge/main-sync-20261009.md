## Agent 交互

- 个人 Agent 会话的输入内容、文件上下文和选中会话在切换协作标签时保留，支持删除个人会话。
- Agent 任务展示阶段、工具调用、思考内容、实时回复、失败原因和重试入口。
- OpenCode 的 `question` 工具可以向任务发起人提问，等待回答期间暂停任务超时计时。
- 项目默认支持三个不同会话的 Agent 任务并行执行；同一会话的任务顺序执行。
- 个人任务、trace 和取消操作按成员权限限制，团队任务向项目成员展示。
- 模型名称在当前任务完成后生效，运行记录保留本次使用的模型名称。
- Monaco 使用本地 worker，文件关闭时保存尚未完成的协作修改并释放文档。

## 知识能力

`agentKnowledgeHooks.ts` 负责任务快照、新增文本区间、知识核对和自我复盘。`agentRunManager.ts` 调用这些函数，并继续负责任务调度、问题回答、取消和运行记录。

- MiniMax 和 DeepSeek 的配置、Key 隔离、知识 MCP 工具继续使用本分支的配置。
- 任务前保留知识预览和排除选项，trace 记录查询、候选、排序参数、实际参考卡片和字符估算 token。
- 成功任务对外显示完成状态时，`usage_summary` 和 `knowledge_post_check` 已写入 trace。
- Agent 文件修改保留修改前后的文本；可明确归属的新增区间登记到对应 run。
- 共享文件同时被成员或其他 Agent 修改时，文件标记 `ambiguous`，相应文本区间不登记为本 run 独占修改。
- 自我复盘与用户任务共用会话执行锁，自我复盘不进入任务列表，用量单独记录。
- 聊天捕获在处理成员消息前记录该成员待处理的光标事件，立即选择消息创建建议时可以使用对应代码位置。
- 规范文档导入导出检查请求路径中的 symbolic link，包括指向工作区内部的链接。

## 人工验收

按照 [分支验收说明](manual-acceptance.md) 配置服务端 API Key，使用 `pnpm dev:demo` 启动系统。Agent 交互流程也可参考 [主分支 Agent 验收](../foundation/agent-main-acceptance.md)。

1. 打开个人 Agent 会话，填写指令并加入文件上下文。切换到聊天后再次进入个人 Agent，检查输入内容仍在。
2. 从两个成员的独立会话启动任务，检查各自看到本人的任务，团队聊天可以查看团队任务。
3. 让 Agent 使用 `question` 询问实现选项，检查发起人可以回答，其他成员无法替代回答。
4. 创建并确认一张团队知识卡片，立即填写相关任务，检查参考知识预览。任务完成后查看参考知识、任务后核对和用量记录。
5. 打开文件并移动光标，发送讨论消息，然后从消息创建知识，检查建议中显示代码候选位置。
