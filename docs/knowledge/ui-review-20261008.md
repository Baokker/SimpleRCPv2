## Pin 与滚动的复现结果

通过编辑器选区执行 Pin，原编辑器区域已经渲染，但标题输入框没有获得焦点。表单位于列表之后，依赖外部容器滚动，成员容易看不到填写入口。当前编辑器使用面板内对话区域，独立正文滚动；端到端测试检查其边界完全位于 `.collab-tab-body` 内，并检查标题输入框焦点。

创建 18 张真实卡片后，导览列表的 `clientHeight` 与 `scrollHeight` 同为 1578，列表随内容增高，无法独立滚动。当前 `.knowledge-panel` 限定面板高度，`.knowledge-view-content` 使用剩余高度和独立滚动。测试使用鼠标滚轮检查内容区 `scrollTop` 增加，外部 `.collab-tab-body` 的 `scrollTop` 为零。

未读计数使用当前成员 id，WebSocket 通知、建议已读和升级申请读取通过同一刷新过程计算总数。端到端测试检查两名成员读取后角标消失，以及一条建议和一条升级申请合计显示 2。

## 不同处理与使用边界

服务端现有升级接口提供申请与确认，没有驳回接口。根据本轮“服务端接口不变”的要求，界面提供“暂不确认”：在当前成员的浏览器会话中隐藏申请，可通过“显示暂不确认的申请”重新查看。这个操作保留服务端申请，其状态仍为 `proposedTeam`，界面不会把它显示为已驳回。

编辑与归档按钮按属主和确认人权限显示；复制链接与查看锚点对可见卡片提供。升级申请已读与暂不确认状态保存在 `sessionStorage`，不同浏览器会话分别记录。

知识面板在成员加入项目后保持其编辑与请求状态。切换聊天或 Agent 标签可以暂时隐藏知识面板，返回后继续编辑或查看生成结果。建议、提醒与升级申请在待处理内容可见时记录已读；编辑器打开期间保留未读。卡片首次查看记录仅在详情实际显示时写入。

导出正文使用 Markdown 引用块，正文内部标题和列表可以保留层级；适用文件与 glob 使用 inline code 保留字符。OpenCode 读取文件的配置方法见 [MCP 与导出说明](mcp.md)。

## 第二轮

### Agent 候选为空的根因与验收

提供的 README 任务记录使用查询“完善一下这个项目的README”，活动文件为 `README.md`。词法分词把连续中文和 ASCII 标识符合为一个查询词；`createProjectStatus给它新增一个内容` 也有相同问题。`bounded` 检索在词法阶段没有传入活动文件，并删除了词法分为零的卡片，后续的文件相关加分无法使用这些卡片。

`packages/knowledge/src/retrieval/index.ts` 分别提取 ASCII 标识符与中文，中文通过 `Intl.Segmenter` 分词；与活动文件相关的卡片进入候选集合。`retrieval/ranking.ts` 使用相同候选集合和已有排序参数。代码位置、文件路径、项目范围与 glob 均参与文件相关判断，索引内容哈希包含 `appliesTo`。

`knowledgeInjection.test.ts` 通过真实卡片和 Agent run 接口，创建有效团队卡片后立即下达 README 任务，检查 `knowledge_injected.candidates` 与 `cards` 都包含它。另一个用例检查中文紧接 `createProjectStatus` 的查询。`knowledgeUiReview.test.ts` 检查没有词法命中时，文件相关卡片仍进入候选。

浏览器验收创建“README，请全部使用英文”，选择整个文件，然后下达“完善一下这个项目的README”。任务预览和“参考的知识”都显示该卡片。测试运行时构造 README 改写，候选生成、预览、任务 trace、状态变化与详情经过实际 REST、WebSocket、Yjs 和界面。任务截图保存在 `S6-UI-10-readme-agent-*.png`。

### 使用说明与处理方式

新建表单中的“保存”是成员核对后确认手动知识的操作，沿用手动卡片直接成为有效卡片的行为。AI 整理接口返回表单内容，调用本身不会创建卡片或建议。

新建保存完成后，界面切换到知识卡片并清除筛选，使新卡片立即可见。导出规范文件触发工作区目录刷新时，`App.tsx` 和 `workspaceTree.ts` 保留刷新期间新展开的目录内容，并采用已经请求的最新目录结果。

文件重命名后，需要成员编辑关联路径。系统提示原路径不存在，并保留文件规则。待复核的代码关联须由属主或确认人处理；归档保留知识内容和历史。

Agent 结束核对和文件 watcher 具有各自的执行时间。文件内容进入 Yjs 文档后，`projectRuntime.ts` 调用知识关联检查，使已经打开的文件也能根据当前共享文本判断复核状态。服务端集成测试使用已准备的 Yjs 文档和实际文件写入，检查自动通知后的卡片状态。

项目知识动态从现有文件读取，新增事件 payload 提供建议标题、摘要、参与成员及应用关联，存储继续使用已有活动日志。历史较早、没有标题或说明的记录显示“请查看原始证据”，可以打开建议详情读取证据。
