# E3 检索重测方案

- 日期：2026-10-10。
- 状态：用户已确认执行；对照相关集按用户确认的清单口径计算。
- 方法参考：academic-research-suite / experiment-agent，实验设计流程。
- 依据：当前检索实现、E3 已保存结果与用户确认的研究目标。
- 本轮范围：BM25 复现、检索比较与注入通道核验。

## 1. 研究问题与已有依据

研究问题：在相同卡片库和注入预算下，检索方式能否把任务需要的知识提供给 Agent，并在没有相关知识时减少无关内容？

已有记录来自 `knowledge-exp-freeze-v2.2`，代码提交 `efda9418f5aefa18780891f2619e154381491fb4`：

| 条件 | 目标卡片进入前五名 | 六个对照任务返回的卡片数 |
|---|---:|---:|
| bounded | 5/16（31.25%） | 30 |
| BM25 | 11/16（68.75%） | 30 |

两者目标命中差异的精确 McNemar p=0.0703125，现有样本支持方向性改善。五个 BM25 未命中的目标位于第六至第九名，适合检验候选重排。上述数字描述排名；本方案另外测量预算处理后的实际提供结果。

当前实现使用 MiniSearch 7.2.0 的 BM25+，属于本地词法检索，无模型调用、embedding 或向量数据库。M3 重排的效果目前未知。

## 2. 三种比较条件

| 条件 | 检索与选择方式 | 模型 |
|---|---|---|
| A：bounded | 现有词法评分与 bounded 排序 | 无 |
| B：BM25 | 现有 MiniSearch BM25+ 与 bounded 排序 | 无 |
| C：BM25＋M3 | 使用 B 的候选，由 M3 判断适用性、排序并选择零至五张 | minimax / MiniMax-M3 |

BM25 参数维持 `k=1.2, b=0.7, d=0.5`，分词、索引字段和文件加分维持 v2.2。本轮不增加新的文件候选补充算法。

B、C 共用相同的前二十名候选。现有项目级补充规则在相同位置执行，候选记录保留来源；C 的模型判断覆盖全部可供选择的候选。模型选择结束后不追加其未选择的卡片。实现时需要验证候选集合与现有补充规则的执行顺序，写入冻结配置。

M3 接收任务原文、实际活动文件，以及候选的标题、摘要、正文、类型与适用范围。提供给模型的正文使用统一的单卡字符预算，记录截取情况。候选以临时编号表示，屏蔽实验目标编号及标签，不提供目标答案、判定器或参考补丁。候选展示顺序在每次重复中按预先固定的种子打乱，模型只允许返回已有编号和选择理由。

三个条件使用相同的可见性、有效状态过滤、最终至多五张限制和注入格式。建议沿用服务端当前默认预算：每张正文最多800字符，整段知识最多4000字符；最终配置在运行前记录哈希。重复卡片处理、项目级补充和预算处理均留下逐条记录。

## 3. 主表只保留三个评价维度

| 维度 | 主表内容 | 计算方式 |
|---|---|---|
| 目标送达 | 目标卡片提供率 | 陷阱任务中，目标卡片出现在最终知识段中的比例；同时报告命中任务数/任务总数 |
| 无关干扰 | 对照误提供率 | 对照任务中，最终知识段包含至少一张预先标注相关集之外卡片的比例 |
| 使用成本 | 每次请求费用与额外等待时间 | 记录 token、费用及计费依据，主表显示平均费用、等待时间中位数与 P95 |

费用按接口实际用量计算；只能估算时明确标注。A、B 的模型费用为零，仍记录本地耗时。

候选前二十名命中、排序前五名命中、预算排除、调用失败、来源计数仅用于解释问题。Recall@1、Recall@3、MRR、nDCG 不进入主表。

提供率按卡片身份计算；若正文预算省略了关键规则，需要在案例表中注明，不能据此声称 Agent 已经获得完整规则。

## 4. 数据与运行数量

使用当前16个陷阱、6个对照，保留所有任务。每个任务包含两种查询：

1. 原始查询：用于重测已有结果。
2. 自然语言改写查询：每个任务一条，保留功能要求、接口要求及原有文件上下文可用性；不添加目标卡片独有的提示词。

共44条查询。改写内容在查看新增条件输出前完成并确认；保存于平台实验目录，数据仓库保持只读。六个对照任务的相关集与逐条依据保存在 `e3-retest-protocol.json`。标注由单个审阅者根据任务要求与完整卡片正文完成，尚无独立标注者一致率。是否提供任何卡片作为辅助统计。

这些任务已经用于检索开发。改写查询测量措辞变化下的稳定性，与原任务共享知识目标；二者不能作为44个独立任务，也不能据此声称对新项目具有普遍效果。

| 内容 | 数量 |
|---|---:|
| A、B 主比较 | 44条查询 × 2种条件 = 88次本地检索 |
| C 主比较 | 44条查询 × 3次重复 = 132次 M3 请求 |
| BM25 历史复现 | 原 v2.2 协议176条本地查询，保存到独立目录 |

三次 M3 重复用于观察模型随机性和候选展示顺序的影响。原查询与改写查询分别汇总；统计单位始终为原始任务。无需运行 Agent 编程任务即可完成本次 E3，Agent 是否遵守知识由 E4 测量。

## 5. BM25 复现与线上核验

历史复现使用 v2.2 的协议、卡片、查询和参数，逐条比较候选排名，核验 BM25 的11/16及 bounded 的5/16。确定性重测不增加统计样本量。

新比较调用产品的检索、选择和知识段生成函数，读取预算处理后的卡片列表。通过实际服务端预览与注入入口核验同一输入的候选与选择结果，不以单独的离线排序代替提供结果。

服务端测试使用真实卡片数据与真实 HTTP。C 的模型请求使用 M3，保存经脱敏的输入、选择结果与用量；不以模拟模型输出作为效果证据。

## 6. 统计与采用判断

主比较为 C 相对 B；B 相对 A 用于验证 BM25 改善。原查询为主分析，改写查询为稳定性分析。

- C 对每个任务按三次重复的二元结果取多数，同时报告逐次结果和三次一致率。
- 目标提供率报告任务数、百分点差异、按任务配对 bootstrap 的95%置信区间和精确 McNemar 检验；两项主比较使用 Holm 校正。
- 六个对照报告明确计数及区间。样本量有限，不以不显著声称两种方法等价。
- 调用失败在端到端目标提供指标中计为未提供；对照中的失败不算正确拒绝，另列失败数量。禁止通过失败返回空结果提高无关干扰指标。
- 原查询与改写查询的差异按原始任务配对分析，不把模型重复或改写次数作为独立样本。

建议的采用规则：相对 B，C 的目标提供数不减少、对照误提供数不增加，且至少一项严格改善；原查询与改写查询均需满足。费用和等待时间同时公开。该规则用于工程选择，论文中的改善结论仍按检验结果与区间表述。

本次 M3 总费用上限为30元，重排等待时间目标为 P95 不超过15秒。这两项为用户确认的工程预算。费用超过预算时暂停；等待时间未达到目标时保留结果并说明使用代价。API 用量缺失时不声称费用符合预算。

## 7. 运行约束与交付

用户审阅通过后，完成实现、真实通道测试、查询与相关集确认，再记录新的代码、配置、提示词、卡片和数据哈希。旧冻结标签与结果目录保留。

M3 单次请求超时建议120秒，失败记录独立保存。本次效果比较不自动重试、不使用其它检索结果代替成功的 M3 结果。所有132个预定请求均保留状态，不能只选择成功结果。

冻结后完整执行预定集合并保留全部结果。需要调整算法、提示词或标注时建立独立协议与结果目录，不覆盖本次结果。

交付包含：三条件主表、BM25逐条复现结果、44条查询的逐项记录、目标未提供原因、对照误提供案例、模型失败清单、费用与时延、线上入口一致性测试记录。更新 E3 报告，并明确区分历史排名结果与本次最终知识段提供结果。

执行协议为 `experiments/knowledge/e3-retest-protocol.json`，包括三个条件、两个效果指标及成本维度、44条查询与132次 M3 请求规模，以及费用和等待时间预算。
