# Agent 协作后续事项

## 任务意图与计划检查

- [ ] 扩充不同属主 Agent 的意图冲突检测。比较任务目标、计划范围、预期输入输出及约束，识别同一业务目标的不同要求，以及不同任务之间的接口依赖。
- [ ] 检查计划变化与任务执行之间的同步。冲突协商期间暂停相关修改；双方确认后，将共同方案提供给各自 Agent，检查后续计划与代码是否遵守共同方案。
- [ ] 明确检查失败、计划缺失、Agent 忽略共同方案时的处理方式，并向属主显示检查状态与需要处理的原因。
- [ ] 准备真实双 Agent 用例，包括同一促销的五折与八折、修改返回值与使用返回值、不同函数之间的依赖。分别记录意图检查、代码检查、协商结果与最终测试结果。

已有入口：`apps/server/src/conflictGuard/intentReview.ts` 检查任务意图，`projectArbitration.ts` 在任务开始、计划变化及实际范围变化时组织检查；`packages/conflict-guard/src/coordination/intents.ts` 保存计划和实际范围。当前的促销规则覆盖明确的折扣矛盾，full 模式也调用模型检查任务与计划。更广泛的意图冲突识别仍需要评价。

## Agent 的符号范围协调

- [ ] 研究使用语法分析得到的函数、方法、类成员范围，为 Agent 申请可见的修改预约。记录 run、属主、符号、文本版本、有效期和等待原因。
- [ ] 明确同一符号修改与依赖符号修改的处理方式。不同函数可以并行修改；修改签名、返回类型和导出状态时检查调用方；相关预约发生冲突时协调执行顺序。
- [ ] 将符号预约与现有写入前检查、文件版本检查、任务完成后复检共同验证。多人编辑和 Agent 修改同一文件时，保留双方已经完成的修改。
- [ ] 明确预约的释放时机，包括完成、取消、失败、超时、会话删除和服务关闭；在界面显示谁正在等待哪个符号。
- [ ] 评价不同属主 Agent 的处理方式：双方协商、自动等待、属主让路。记录任务成功率、等待时间、打扰次数与冲突遗漏。

现有 Agent 修改通过 `packages/conflict-guard/src/coordination/agentGuard.ts` 进入符号级检查。待审批修改可以等待属主处理。符号预约的具体规则和界面仍需要进一步讨论与验证。
