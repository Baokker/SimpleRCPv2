# 智能语义冲突预防：实验问题、指标与开发集结果

## 材料信息

日期：2026-10-10。分支：`feature/conflict-guard`。基础提交：`18723f1`，加本轮提示词版本与统计脚本的工作区改动。分析源码与原始结果的 SHA-256 见 [统计核验](../evidence/focused-evaluation-analysis/verification.json)。

本报告使用开发集、真实模型录制和 Agent 功能验收记录。正式保留集尚未执行，冻结状态仍为 `awaiting-human-confirmation`。GreyLock 不作为本报告的比较对象。模型使用 **MiniMax-M3**，国内站 `https://api.minimaxi.com/v1`，关闭推理，温度为 0，每次最多输出 1024 token，研判时限 8 秒。

## 实验围绕哪些问题

| 问题 | 实验内容 | 主要指标 | 结论适用范围 |
|---|---|---|---|
| 人与人协作能否及时发现冲突，同时减少不必要的阻止？ | 在相同编辑轨迹上比较无协调、文件锁定、相关符号锁定、本地分区 | 未及时通知的冲突写入比例、安全修改误拦率、冻结人秒 | 回放中的识别和干扰成本 |
| 灰区交给模型后，能否作出可靠、及时的判定？ | 相同开发集、相同模型和时限，比较三个提示词版本 | 完成率、漏阻断率、误拦率、提醒比例、有效回答延迟 | 当前模型与输入条件下的表现 |
| Agent 能否完成任务，并在冲突发生时处理拒绝？ | 工具兼容性验收、拒绝后修正、相同任务的意图注入比较 | 任务验收通过率、拒绝后修正比例、属主处理次数、等待时长 | 功能是否可执行，以及特定任务中的协作表现 |

索引性能和规则命中数可以作为工程补充。模型替换与多项消融不单独作为这三个问题的完成条件。

## 指标怎样理解

| 指标 | 计算方法 | 需要同时说明的内容 |
|---|---|---|
| 未及时通知的冲突写入比例 | 冲突文本已经写入、且此前没有提醒或阻止的样本数 ÷ 冲突真值样本数 | 提醒也算通知；低数值不能独立证明冲突已经修复 |
| 漏阻断率 | 真值要求拦截、最终决策却为放行或提醒的样本数 ÷ 要求拦截的样本数 | 当前实现使用整段轨迹的最终决策 |
| 安全修改误拦率 | 真值允许放行、最终决策却为拦截的样本数 ÷ 安全样本数 | 中途发生的冻结另外计入冻结人秒 |
| 冻结人秒 | 所有冻结区间的持续秒数乘以受影响人数后求和 | 两个人同时等待 5 秒计为 10 人秒；回放值依赖预设的协商事件 |
| 决策一致率 | 最终决策等于可执行标签的样本数 ÷ 有效样本数 | 当前没有提醒真值，无法评价“正确提醒”的识别能力 |
| 请求有效响应率 | 格式有效且在时限内完成的 HTTP 请求数 ÷ 全部 HTTP 请求数 | 超时、格式无效均保留在分母中 |
| Agent 任务验收通过率 | 最终源码通过预定验收的任务数 ÷ 尝试任务数 | `completed` 状态和源码通过验收分别报告 |
| 拒绝后自行修正率 | 发生拒绝后完成正确调整的 run 数 ÷ 实际发生拒绝的 run 数 | 未触发拒绝的任务不能算修正成功 |

比例附 Wilson 95% 区间；同一关系组的多个变体存在关联，统计比较以关系组为单位。配对检验使用 exact two-sided McNemar；同一实验内全部比较使用 Holm 校正；关系组 bootstrap 2000 次，种子 `20261007`。McNemar 检验的是关系组决策正确性，不能用它证明冻结时长存在显著差异。

## 人与人协作回放

本轮使用 D1-v3 开发集，按四状态程序去重后为 119 个有效样本，来自 97 个关系组。其中 22 个要求拦截、97 个允许放行。五种策略使用相同样本与标签。

| 策略 | 未及时通知的冲突写入 | 安全修改误拦 | 冻结人秒 | 漏阻断率 |
|---|---:|---:|---:|---:|
| 无协调 | 22/22，100% | 0/97，0% | 0 | 100% |
| 文件锁定 | 9/22，40.9% | 42/97，43.3% | 5151.45 | 40.9% |
| 相关符号锁定 | 3/22，13.6% | 49/97，50.5% | 4062.39 | 27.3% |
| 本地语义分区，灰区提醒 | 4/22，18.2% | 0/97，0% | 333.21 | 59.1% |
| 候选对内使用真值的参考策略 | 4/22，18.2% | 0/97，0% | 646.53 | 27.3% |

本地语义分区的冻结人秒比文件锁定减少 93.5%，比相关符号锁定减少 91.8%。97 个安全样本没有最终误拦，Wilson 95% 区间为 0%–3.8%；未及时通知的冲突写入为 4/22，区间为 7.3%–38.5%。这些数值支持“在本开发集回放中减少冻结成本，同时减少未及时提示的冲突写入”的观察结论。

本地分区对 46/97 个安全样本最终给出提醒，仍有打扰；22 个要求拦截的样本只有 9 个最终判定为拦截。因此报告同时保留 59.1% 的漏阻断率，不能把较低的未通知比例解释为完整预防冲突。相关符号锁定少出现一次未及时通知，同时冻结成本和安全误拦更高。

使用真值的参考策略也有 4 个样本未及时通知。该策略只替换已有候选对的决策，候选生成和检查时序仍受系统限制。它不能代表拥有全部程序信息且能提前阻止所有修改的理想系统。

原始结果：[人与人回放](../evidence/focused-evaluation-human-dev/results.json.gz)。各策略统计和区间见 [统计核验](../evidence/focused-evaluation-analysis/verification.json) 的 `human` 与 `statistics.human`。

## 灰区模型研判

### 评价范围

灰区子集由本地分区实际触发模型请求的轨迹确定，选取过程不读取模型输出。在全部 119 个样本中，61 个进入该子集，涉及 54 个关系组；其中 12 个要求拦截、49 个允许放行。

以下质量指标衡量这些轨迹的最终决策。原始标签针对完整修改，无法直接给每一个编辑中间状态赋予相同真值，因此这里也不将每次 HTTP 调用当成独立的分类样本。

### 三个提示词版本的结果

默认版本 `pair-v1` 根据双方代码和共同使用行为判定；`pair-v2` 增加具体失败证据的要求；`pair-v3` 进一步列出删除仍被引用的符号、调用签名不兼容、返回值使用等检查项。三个版本分别保存缓存，默认版本保持 `pair-v1`。

| 灰区指标 | 默认提示词 | 强调具体证据 | 增加证据检查顺序 | 预设门槛 |
|---|---:|---:|---:|---:|
| 决策一致率 | 15/61，24.6% | 17/61，27.9% | 31/61，50.8% | ≥80% |
| 漏阻断率 | 3/12，25.0% | 8/12，66.7% | 7/12，58.3% | ≤10% |
| 安全修改误拦率 | 7/49，14.3% | 1/49，2.0% | 2/49，4.1% | ≤15% |
| 安全修改收到提醒的比例 | 36/49，73.5% | 35/49，71.4% | 21/49，42.9% | 尚无预设门槛 |

第三个版本识别出更多安全修改，但需要拦截的 12 个样本中只有 5 个最终判定为拦截，少于默认版本的 9 个。没有一个版本达到全部质量门槛，两个探索版本均未替换默认配置。

默认版本与第三个版本的关系组正确性比较，Holm 校正后 p=0.00273；一致率相差 26.2 个百分点。第三个版本的一致率关系组 bootstrap 区间为 39.1%–63.2%，漏阻断率区间为 33.3%–83.3%。正确性改善主要来自安全样本，不能据此宣称拦截能力改善；这些比较属于开发集探索。

全部 119 个样本的一致率依次为 58.0%、59.7%、71.4%，其中包含本地规则处理的样本。这些数值用于观察整个系统，不用来替代上表中的灰区质量。

### 请求完成情况与延迟

| 指标 | 默认提示词 | 强调具体证据 | 增加证据检查顺序 |
|---|---:|---:|---:|
| HTTP 请求数 | 184 | 184 | 184 |
| 有效响应 | 139，75.5% | 80，43.5% | 147，79.9% |
| 超时 | 36 | 94 | 25 |
| 格式无效 | 9 | 10 | 12 |
| 轨迹中计入判定的任务完成率 | 62/75，82.7% | 29/64，45.3% | 55/65，84.6% |
| 计入判定的任务延迟 p50 | 5263 ms | 7480 ms | 5609 ms |
| 计入判定的任务延迟 p95 | 8000 ms | 8000 ms | 8000 ms |
| 已知 usage 对应费用，估算 USD | 0.130714 | 0.075014 | 0.140935 |

预设完成率门槛为 95%，p50 门槛为 3000 ms，各版本均未达到。任务完成率来自实际进入回放判定记录的任务，受版本更新与时序影响，三个版本的分母不同；因此同时报告分母均为 184 的 HTTP 请求有效响应率。

p95 包含超时终止值，而请求本身在 8000 ms 时终止。**p95 等于 8000 ms 不能证明 95% 的有效回答在 8 秒内完成。** 成功请求的条件延迟见统计文件中的 `successfulHttpLatencyMs`，它与全部请求有效响应率一起解释，不能排除超时请求后单独宣称达标。

费用依据响应中可获得的 usage 和已保存的价格估算；没有 usage 的失败请求可能仍产生费用。价格为国内站标准档、日期 2026-10-10，记账采用 CNY 7 = USD 1。本表不能替代供应方账单。录制时段不同，完成率和延迟差异也可能受到服务或网络状况影响，当前没有交错重复实验来确定其成因。

### 已发现的问题与改善方向

1. **编辑中间状态的代码不完整。** 默认版本和第三个版本各有 114/184 个请求的至少一侧 after 片段存在 TypeScript 语法诊断，约 62.0%。片段诊断不能直接等同于整个项目的语法错误，但说明模型经常面对不完整证据。实际响应曾把尚未编辑完成的函数片段当成最终程序错误。输入整理应保留完整声明，明确语法是否完整，并区分单侧原有错误与合并后新增错误。仍在编辑的片段需要等待同一变更的新版本后继续检查，同时统计这段等待。
2. **提示词要求的证据没有完整提供。** 当前输入含双方代码、关系路径和合并新增诊断，但没有明确的符号删除状态和完整四状态诊断。`pair-v3` 的部分检查项因此无法直接验证。改善需要补充这些结构化信息，并用开发集用例检查字段是否正确。
3. **模型检查范围与标签范围需要一致。** 例如 `d1-0045-safe` 中模型确认两侧修改已经配合，却因另一个调用点给出提醒。需要明确本次评估针对哪一组共同使用行为；另外的调用风险应单独建立变更对。探针也需要检查它声称覆盖的调用行为，标签不能由模型输出产生。
4. **输出较长，且存在格式失败。** 可以在相同八字段格式下减少重复解释、限制证据条目，并验证完整 JSON 输出和实际耗时。调整后的版本仍使用独立缓存和相同 8 秒门槛。
5. **没有进入最终判定的冲突需要检查调度。** `d1-0026-conflict` 的默认版本记录没有判定，且没有及时通知。应检查批次关闭、持久写入和判定触发时序。提示词无法处理未送到模型的修改。

这五项属于后续实现与验证事项，本轮未将它们全部实现，也没有据此宣称灰区问题已经解决。新的真实录制应在输入与调度核验完成后进行，并使用明确的剩余调用预算。

### 缓存可复现性

第二个版本的一条缓存含 JSON 语法错误，默认版本和第三个版本分别通过 184 条缓存身份核验，第二个版本通过 183 条。错误文件的 SHA-256 和路径记录在统计核验的 `cacheIntegrity.issues`；原始文件和归档保持原样。第二个版本的质量表来自保存的完整 `results.json.gz`，可以重新计算，但整轮缓存回放尚不能宣称完整可复现。

录制器对同一请求的成功与超时记录可能同时保存。缓存写入现在使用顺序队列与独立临时文件名，并通过真实请求记录的并发文件写入测试。本轮没有重新请求模型来覆盖这条缓存。缓存完整性是正式冻结的必要条件；当前材料继续用于开发探索。

### Jev 可用性

最新诊断返回 HTTP 451：`Typesafe is not available in your region.`，模型名为 `jev-1.13.0`。当前无法产生有效的快判质量结果，也无法完成级联阈值校准。Jev 的失败响应不作为模型判定结果引用。人与人本地回放及 MiniMax 独立深判已有各自证据。

## 正式实验保留哪些内容

1. **人与人主比较。** 在相同保留集上运行无协调、文件锁定、相关符号锁定、本地分区及最终确定的模型方案。全部比较条件使用同一组样本，报告冲突通知、安全误拦、冻结人秒与延迟。开发集用来调整方案，保留集只执行冻结的条件和重复次数。
2. **灰区质量比较。** 在开发集确认输入和提示词后固定一个版本。保留集报告实际灰区子集的质量、完成率、延迟、提醒比例与费用。离线 replay 验证可复现性；独立 live 重复验证模型波动与延迟。Jev 可用性单列，不把 451 响应当成快判基线。
3. **Agent 协作验证。** 保留三种代表任务，固定闸门与属主仲裁，比较意图注入开启和关闭，每个条件三次重复。两名 Agent、三种任务、两个条件、三次重复共预计 36 个初始 run，追加执行另计。该设计评价意图注入的增量作用；完整机制的演示使用真实轨迹补充。新的预算及冻结材料需要人工确认。

以上为收缩后的实验设计建议，尚未修改正式协议中的条件、重复次数和预算。现有开发结果不能替代保留集证据。

## 统计解释检查

统计核查覆盖 11 类问题：按算子族保留分组结果；不把任务集合的结果推广到所有协作者；灰区选择仅使用本地规则；不按模型成功与否选择质量样本；同时报告安全与冲突样本数量；单次录制改善不宣称稳定；失败请求保留；三个提示词结果全部保留；探索条件与正式条件分别说明；回放时间不作为真实用户等待的因果证据；请求时间先后可追踪，但未控制网络变化。Wilson 区间是样本比例描述，关系组相关性通过 bootstrap 和配对单位处理。

数据来自合成项目与预定修改算子，关系组之间也可能共享程序模板。可执行探针只证明其覆盖的输入和行为；模型无法访问的上下文、暂未覆盖的业务行为、供应方型号更新及录制时段变化都会限制结论。正式用户研究需要另行测量真实等待、理解程度和协商行为。
