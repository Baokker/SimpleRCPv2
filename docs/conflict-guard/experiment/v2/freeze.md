# v2.1 冻结清单

冻结状态为 `frozen`，用户在 2026-10-19 复核开发集彩排后确认进入阶段 C。源码提交与各文件哈希记录在 `freeze.json`，实验协议在 `protocol.json`，调用预算在 `budget.json`，全部正式命令在 `run-holdout.sh`。冻结之前没有读取任何保留集模型结果或回放结果。

## 与 v2 冻结版本的差异

v2 冻结材料在开发集彩排中暴露出几处问题，按原样执行会得到无效结果，本版本逐项修正。

1. E2 的 G1 配置 `t1Strategy` 为 G1，不是合法值，改为 G2。G3a 配置原先引用关闭推理的 `stage-A3/config.json`，改为开启推理、深判时限 30 秒的 `configs/config-G3a.json`。
2. E2 原定一轮录制加回放，改为三轮在线配对录制，每轮缓存目录独立，同一轮 G3a 读取同轮 G2-v5 的快判结果。
3. E3 运行配置 `t1Strategy` 为 G4，服务启动即报错，改为 T1 使用 G3a，T2 关闭推理、T3 开启推理，T2 与 T3 深判使用 pair-v1，格式无效或请求失败时在时限内重试一次。
4. E3 场景由六个扩充为八个（D3-S-v2），新增 d3-04、d3-05 两个人与 Agent 场景；Agent 任务使用 d3-v0 原任务的完整描述；人的修改由虚拟成员通过协同文档写入，触发时机为 Agent 完成第一次工具调用之后；同属主场景按场景类别设定属主。
5. 方法层面的三处修正已经进入冻结提交。候选关系保留修改前被删去的引用（`4f2af80`）；Agent 写入前检查覆盖解构读取（`ca5616d`）；Agent 基准的执行入口真正经过守卫（`f83d346`）。后两项在开发集 E1 回放上没有改变任何样本的决定。
6. 预算上调为美元 2.5、Agent run 60 次，以容纳 E2 三轮和 E3 扩充。

## 执行顺序

E2 第 1 轮（G2-v5、G3a 顺序执行，G1 并行），然后第 2、3 轮；E1 主行回放第 1 轮缓存，再录制消融；E4 单独运行以免计时受干扰；最后 E3 的 A0 一轮与 A1 三轮。只有代理或网络环境故障（Jev HTTP 451、连接被拒、DNS 失败）可以作废整轮重录，模型超时和格式无效计入分母，输出路径错误时移动已有结果而不重新调用模型。

## 指标

E1 与 E2 的主指标为平衡准确率，即应拦截样本的拦截率与应放行样本的非拦截率的均值，样本按真值划分。E1 另报告逃逸、误拦、安全修改提醒、本地决定比例与冻结人·秒，P4 与 P1、P2、P3 按关系组做精确双侧 McNemar 检验并用 Holm 校正。E2 报告三轮均值与范围、轮间决定不一致的样本数，以及深判改变的决定。E3 为可行性案例，报告写入前拦截是否正确、Agent 与 Agent 场景中的误打断次数、验收通过率是否下降、额外费用与时延。E4 报告索引全量与增量开销及候选对聚合效果。分析脚本为 `rehearsal-dev/analysis/` 下的 `e2_metrics.py` 与 `e1_analysis.py`。
