# 开发集选择规则

日期：2026-10-16。仅使用 D1-v3 开发集；保留集不参与选择。规则在新增模型录制之前提交。

## 比较顺序

1. 深判提示词：已有 `pair-v1` 的 G1 录制，与完整声明和结构化证据输入的 `pair-v4` 的 G1 录制。`pair-v2`、`pair-v3` 仅保留探索记录。
2. 级联阈值：使用选中的深判提示词与同版本输入的 G2 录制，离线比较阈值 `0、0.2、0.4、0.6、0.8`。快判置信度低于阈值、判为 `lock` 或请求无有效结果时升级。深判复用第一步相同输入的 G1 缓存，不新增请求。
3. 完整策略：比较 G1、G2 与选中阈值的 G3，选中者用于 P4。P4 等于 P3 加所选灰区策略。

## 每一步共用的选择顺序

1. 请求有效响应率比同一步最高值低超过 5 个百分点的候选不参与选择。
2. 安全修改误拦率超过 15% 的候选排除；若全部超过，保留误拦率最低者。
3. 取漏阻断样本数最少者。
4. 漏阻断数量相差不超过一个样本时，取决策一致率较高者。
5. 仍相同时，第一步和第三步取有效响应时延 p50 较低者；第二步取升级率较低者。全部相同则按候选登记顺序选择。

若有效响应率要求使候选集合为空，停止选择并报告，不能临时放宽规则。

## 样本与统计

灰区样本由 P3 的本地分区决定，选取时不读取模型输出。共同主表使用上一轮 P3 实际触发的灰区轨迹集合，保持 `pair-v1` 和 `pair-v4` 的样本分母一致；新增或因语法等待未请求的轨迹另列。质量按轨迹最终决策统计，请求有效响应率按全部真实 HTTP 请求统计，超时、格式无效、缺少 usage 分别报告。

有效响应时延仅统计时限内格式有效的响应；语法等待次数和等待时长 p50/p95 单独统计。级联的响应时延包含先后执行的快判与深判，代理时延计入 Jev 时延。费用依据已知 usage 估算，缺少 usage 的调用单独列出。

`pair-v1` 使用已有录制，输入整理与录制时间与 `pair-v4` 不同，这些差异在报告中注明。选中旧提示词时，新 G2 与 G3 使用完整声明输入，并与该输入对应的深判录制比较；若已有缓存无法覆盖，需要在预算内录制并单列调用数量。

## 版本与预算

深判为 MiniMax-M3，国内站直连，关闭推理，温度 0，最多输出 1024 token，时限 8000 ms。快判固定 Jev `jev-1.13.0`，通过 `TYPESAFE_PROXY_URL` 代理，choice 接口；输入版本为 `declaration-evidence-v1`。

新增开发集深判最多 400 次，快判最多 600 次；代理连通验证另计 3 次。所有失败请求计入预算。开发集完成后报告并等待确认；本阶段不执行保留集。
