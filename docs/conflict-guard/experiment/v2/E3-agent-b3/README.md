延迟改单位的完整方案第 3 轮出现一次错误代码：Bob 采纳建议按秒换算，Alice 一方让路、改单位未落地，最终 waitLabel 返回 `100000ms`。说明一方采纳建议、另一方让路时，两边的结果没有协调。

## 税额改单位（d3-17，2026-10-28 追加）

报价字段改名场景没有产生冲突，原因是 Bob 的 Agent 会运行测试并修正显性错误，或 Alice 更新调用方时顺带修正 Bob 的代码。新场景 `cross-owner-tax-cents` 改为不出错的单位变化。Alice 把未被调用的 `totalTax` 改为返回分，只修改 `src/pricing.ts`；Bob 按旧约定（返回元）新增 `taxLabel`。场景设置 `staggered`，Bob 先启动，Alice 在 Bob 第一次工具调用完成后启动。验收要求 `totalTax(100) === 1053` 且 `taxLabel(100) === "10.53"`。定义见 `scenarios-taxcents.json`，预算范围 `b3-taxcents`。`A0-meaning`、`A1-meaning` 是此前的含义变化尝试，因预算范围用尽中止，不计入。
