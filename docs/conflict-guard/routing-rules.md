# 分区规则求值顺序

配置版本为 `routing-run-2`。候选生成前，用 TypeScript AST 比较语法结构与 token 内容，过滤注释、空白与缩进修改。字符串内容、正则表达式与换行引起的语法变化保留。仅修改注释的批次记录 `change_unit.commentOnly=true`，符号列表为空。声明之间的注释与空白不产生符号变更，也不产生 T0 提示。

候选生成以参与者对和批次中的符号簇为单位。同一批次内，一跳相关或具有包含关系的符号合并为一个簇；簇之间保留全部关联路径，形成一个变更对。仅通过 `type-reference` 相连、并且路径中的类型没有被参与者修改时，计入无关系单元。修改类型本身、调用关系和运行时引用继续形成候选。

每个簇的所有关联都使用下面的分类器，严重程度最高的结论作用于整簇。模型输入、冻结范围和写入闸门涵盖全部簇成员。判定缓存使用 pairId、revision 和输入指纹；公开结果没有变化时不再发布 `pair_judged`。`CONFLICT_GUARD_JUDGEMENT_FRAME_MS=200` 与 `CONFLICT_GUARD_MAX_JUDGEMENTS_PER_FRAME=20` 控制判定队列的合并窗口与每次处理数量。

分类器预先检查引用删除、导出删除、调用签名、返回属性和接口成员不兼容，供白区规则使用。之后按下面的顺序选择结果。

| 顺序 | 规则 | 结果与条件 |
|---|---|---|
| 1 | `comment-only-edit` | 两侧都仅修改注释或空白，白区放行。 |
| 2 | `comment-format-only` | 一侧仅修改注释或空白，双方没有已确认的接口不兼容，白区放行。 |
| 3 | `observability-only` | 一侧仅修改无副作用的日志，双方没有已确认的接口不兼容。同声明任一侧改变公开接口时继续检查。 |
| 4 | `declaration-body-unrelated` | 同一声明、修改行距离超过配置值，四状态检查完成且没有合并独有类型错误，两侧公开接口及推断返回类型保持不变，灰区警告。 |
| 5 | `same-symbol-concurrent-write` | 其余同符号或包含关系的并发修改，黑区冻结。 |
| 6 | `type-only-unchanged` | 仅类型关联且类型接口保持不变，白区放行。 |
| 7 | `equivalent-refactor` | 等价重构且没有已确认的接口不兼容，白区放行。 |
| 8 | `referenced-symbol-removed` | 删除仍被使用的符号，黑区。 |
| 9 | `runtime-export-removed` | 删除仍被使用的运行时导出，黑区。 |
| 10 | `call-signature-incompatible` | 调用签名不兼容，黑区。 |
| 11 | `consumed-return-property-removed` | 删除调用方读取的返回属性，黑区。 |
| 12 | `interface-required-member-incompatible` | 接口必需成员不兼容，黑区。 |
| 13 | `merge-only-type-error` | 合并状态独有的类型错误，黑区。 |
| 14 | `unparsable-side` | 暂时无法解析，灰区。 |
| 15 | `semantic-interaction-uncertain` | 其余有关联的修改，灰区。 |

无副作用的白区情形优先结束判断，因此注释与空白不会进入同声明冻结规则。日志参数中的函数调用保留语义检查。相邻行仍然使用同声明并发修改规则；参数、返回类型和导出变化也继续检查黑区。

`CONFLICT_GUARD_BODY_ADJACENT_LINES=3` 表示两侧任意修改行范围之间的距离不超过 3 行时视为相邻。例如第 4 行与第 8 行的距离为 4，可以进入 `declaration-body-unrelated`；第 4 行与第 7 行的距离为 3，继续检查黑区。配置必须为非负整数，写入服务端 `session_start.config`，回放读取相同数值。

`declaration-body-unrelated` 的结果带 `localOnly=true`，在 `rules` 和 `full` 中保持本地灰区警告。该规则判断修改位置与公开接口，不证明两处计算完全独立；用户仍需检查警告。其他灰区继续使用所配置的模型策略。

同一声明的四状态检查分别构造基线、仅左侧、仅右侧与合并文本，每个状态只替换声明一次。检查使用 TypeScript TypeChecker 比较返回类型，包含未填写类型标注的函数、方法、变量与类属性中的函数表达式。支持 `.ts`、`.tsx`、`.js`、`.jsx`、`.mts`、`.cts`、`.mjs` 与 `.cjs`。检查超时或无法组合修改范围时继续使用同声明黑区保护。

人的累计修改和 Agent 提案都过滤注释范围。逐字符输入完成后，语义范围按当前完整修改重新计算。T0 在语义索引更新时检查仍然打开的批次：从空白、注释或暂时无法解析的输入开始，后续出现可解析代码修改时仍能提示；同一批次与变更对只提示一次。

可解析文本通过 TypeScript AST token 序列比较生成语义范围。代码与成对块注释、长注释同时修改时，只记录变化的代码 token。字符串、正则、JSX 和自动分号插入引起的语法变化仍然记录。整个声明被注释禁用时，按该成员删除符号处理；仍然存在的调用继续参与黑区检查。

全文替换与局部编辑按文本前后的实际差异维护归属范围，原始 Yjs 操作继续记录在轨迹中。全文替换后其他成员修改范围外的代码时，双方的符号 before/after 仍保留各自的修改归属。

Agent 的 T2 与 T3 使用同一份精确语义范围。T3 根据共享文本后续修改移动范围，按 `changedSymbols` 限定复检符号；历史记录保存范围对应的文本，用于重新计算位置。删除符号继续保留显式删除键。
