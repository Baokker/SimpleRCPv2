# 阶段 5

`src/adjudication/` 提供两个角色接口、适配器注册、共享上下文、规范化提示词、截止时间、取消与缓存。会话协调器增加 analyzing 状态，模型结果通过同一状态机生效。服务端 full 模式启用灰区模型处理，WebSocket 推送完整的成员状态快照；客户端显示黄色区域、解释、建议、来源、置信度、延迟与费用。rules 和 observe 保留本地规则行为。

## 实现与验证范围

Jev 固定 `jev-1.13.0`，使用直接 Choice；DeepSeek 使用环境配置的 `deepseek-flash`，T1 关闭 thinking，严格验证 JSON。共享上下文自动收集调用点、函数签名、调用行前后三行、测试名称及断言、修改前注释与返回值用法。每侧至多三个调用点，各文本字段最多 3000 字符，可通过配置关闭 invariants。

G0 为 warn，G1 为深判，G2 为快判，G3 在低置信度、lock 或失败时升级，G4 的 T1 角色选择通过配置确定。缓存与请求受 8000 ms 总时间预算限制，较晚加入的订阅者保留自己的剩余预算，变更对修订中止旧订阅。没有活动订阅者时中止 HTTP。失败降级为 warn，保留错误计数及已经发生的 token 费用。

回放复用相同的输入构造与会话协调器，以录制延迟推动虚拟时钟。缓存包含经过脱敏的原始响应，轨迹只包含 provider_call 元数据与输入哈希。对象属性名也执行脱敏；损坏缓存按失败处理。

原始 D1 开发集有 18 个关系组、28 个去重样本，其中 lock 真值 8 项、allow 18 项、warn 2 项。开发集主表沿用这些分母。原始数据只有十个可用于冒烟的不同灰区关系组，因此另外生成 `stage5-dev-smoke-v1`：只使用原开发项目 billing、calendar 及 IC、CP、SF，得到 105 个关系组、151 个已标注非 alias 样本。每种状态运行三次，无剔除项；其中二十个不同灰区关系组用于实际调用。保留项目、保留算子族和保留集均未参与。

## 已知限制与阶段 6 接口

共享上下文依赖静态关系和测试写法。间接调用、动态共享状态与未被探针覆盖的业务行为仍可能缺少证据；3000 字符限制可能截断上下文。本次校准样本数量有限，置信度不能直接解释为冲突正确率。实际模型可能在相同输入上产生不同结果，研究重现通过固定录制完成。

离线 record 准备阶段会对发现的输入调用模型，实际应用的判定数量可能因后续修订取消而减少。报告分别保存 HTTP 调用与状态机模型判定；实时请求取消能力由服务端及浏览器验证。当前模型录放策略没有自动从真实服务端轨迹恢复适配器缓存目录，需要调用者明确提供配置和录制响应。

阶段 6 可以复用两个角色接口、输入哈希、取消、缓存与状态机。Agent 的 T2/T3 应通过明确时点参数选择处理方式，继续单独定义失败动作；本阶段 T1 始终降级为 warn。建议保持开发集与保留集的使用边界，并将来源、提示词版本、上下文开关和模型版本写入 Agent 轨迹。
