# 冲突界面与注释编辑修复

验收日期：2026-10-08。开发分支：`feature/conflict-guard`。修改前提交：`9365ee9`。实现提交：`0b884a0689ad47d0c91a004912d3980f5951e90d`。

## 1. 三个用户场景

| 操作 | 当前结果 | 验证位置 |
|---|---|---|
| 一人修改 `console.log('aaa')` 的文字，另一人修改同一函数的计算 | 无副作用的日志修改进入白区，放行并保留双方内容。日志参数包含函数调用时继续进行语义检查。 | `routing/comment-body.test.ts`；服务端 `console.log 内容修改与同函数计算修改放行并写入双方内容` |
| 一人在函数或类体内增加、修改注释，另一人修改代码 | 注释不产生符号变更，不参与同声明并发修改判定，不触发冻结。 | `routing/comment-body.test.ts` 的类体注释、注释文字修改用例；服务端注释集成用例 |
| 在已有注释前按回车，再输入注释 | 回车、缩进和注释不产生符号变更或 T0。逐字符输入完成后仍保持这一结果。 | 服务端 `逐字符输入回车与注释后不生成符号修改与 T0` |

## 2. 注释过滤与规则

`semantic/trivia.ts` 使用 TypeScript AST 比较语法结构与 token 内容，保留字符串内部空白、正则表达式以及换行引起的语法变化。`tracking/tracker.ts` 同时维护普通修改范围和 `semanticRanges`：普通范围用于保存与撤回，语义范围用于符号映射、候选生成与 T0。`semantic/changes.ts` 根据当前共享文本恢复该成员修改前的符号文本，并记录实际修改的行范围。

仅修改注释或空白的批次仍写入轨迹，`change_unit.commentOnly=true`、`symbols=[]`。这类批次不计入有效符号变更单元。声明之间的注释、空行与缩进不归入相邻声明。

规则依次求值：`comment-only-edit`、`comment-format-only`、`observability-only`、`declaration-body-unrelated`、`same-symbol-concurrent-write`，再继续其余规则。无副作用的白区情形优先结束判断，注释、空白与日志文字不会被同声明规则提前冻结。引用删除、导出删除、调用签名、返回属性与接口成员不兼容仍会预先检查，供白区规则使用。完整顺序见 [routing-rules.md](routing-rules.md)，方案设计 D2 表格同步更新。

新增 `declaration-body-unrelated`：双方修改同一声明、全部修改行范围互不相邻、四状态检查完成且没有合并独有类型错误、公开接口与推断返回类型保持不变时，给出本地灰区警告“双方正在修改同一声明的不同部分，请留意修改之间的影响”。结果带 `localOnly=true`，`full` 模式也保持警告。任一侧改变参数、返回类型或导出状态时，继续检查黑区规则。相邻修改与同位置覆盖仍使用原有黑区保护。

新增配置：

```dotenv
CONFLICT_GUARD_BODY_ADJACENT_LINES=3
```

该值必须为非负整数。两侧任意修改行范围的距离不超过此值时视为相邻。第 4 行与第 7 行的距离为 3；第 4 行与第 8 行的距离为 4。配置版本为 `routing-ui-1`，服务端、Agent 检查与回放共用该参数，轨迹 `session_start.config` 记录实际数值。该本地灰区规则计入本地决定统计。

## 3. 界面

- “冲突预防”页签使用与其他页签相同尺寸的图标；角标统计与本人有关的待处理人类冲突，以及等待本人处理的属主卡片。数量为零时隐藏。
- 冲突卡片依次显示标题、区与动作及规则标签、摘要、模型解释和建议、双方符号、关系路径、可展开的双方修改前后代码。
- 操作使用同一纵向列表，每项高度 36px，图标和文字左对齐。顺序为“我来改”“双方确认后继续”“去聊天里商量”；确认后显示完成状态并禁用该操作。
- 卡片、关联条目与通知复用现有主题颜色。解释和建议按中文句末标点换行，超过三行可以展开或收起。
- 关联修改以身份与符号、区与动作及规则和关系路径分别显示，路径使用“甲 调用 乙”等短句。
- 编辑器顶部显示单条可折叠横幅。横幅占用独立空间，展开后显示当前文件的冲突列表；代码区域保留冻结装饰和悬停提示。

修改前后共 10 张截图及复现命令见 [截图目录](evidence/ui-round1/README.md)。截图使用两个独立 Chromium 上下文，验证依据包括 DOM、真实接口状态与元素尺寸。

## 4. 开发启动

从仓库根目录执行 `pnpm dev`，服务端随源文件变化重新启动。重新启动期间页面可能出现 500，Vite 可能显示 `ws proxy error: socket hang up`。监听恢复后刷新页面即可。服务端启动日志包含 ISO 时间戳和监听地址；客户端收到 HTTP 500 时提示“服务端可能正在重启，请稍后刷新”。

人工验收可执行：

```bash
pnpm dev:stable
```

该命令同时启动前后端，服务端只启动一次。单独启动服务端使用 `pnpm --filter @simplercp/server dev:once`。修改 `.env` 或服务端代码后，需要结束命令并重新启动。配置与人工步骤见 [manual-acceptance.md](manual-acceptance.md)。

## 6. 使用范围

`declaration-body-unrelated` 依据修改位置与公开接口给出警告，两处计算仍可能相互影响，用户需要检查提示。暂时无法解析的输入继续按现有规则处理；T0 等待可解析输入。

本轮改变了规则顺序并增加实验参数。正式实验执行前，需要人工重新确认冻结清单，记录 `routing-ui-1`、相邻行阈值和本轮提交号。

模型缓存以录制时的规范化输入哈希匹配。本轮的符号修改范围和成员修改前文本可能产生新的输入；离线校验中，缓存未命中仍按失败处理。正式模型评价需要在人工确认后的冻结配置下录制。

类型检查、混合注释、T0 与 Agent 范围的复核结果见 [review-ui-round1.md](review-ui-round1.md)。
